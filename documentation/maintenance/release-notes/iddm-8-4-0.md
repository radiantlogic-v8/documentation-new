# RadiantOne Identity Data Management v8.4.0 Release Notes

April 28, 2026

These release notes contain important information about improvements and bug fixes for RadiantOne Identity Data Management v8.4.0

## New Feature

- [API-3313]: Added Custom Tasks feature to allow users to upload custom task Java classes and create new custom task instances based on those Java classes.

## Improvements

- [API-3277]: Migrated Password Policy configuration from the Classic Control Panel into the new Control Panel. 
- [API-3256, SQ-618]: Updated the File Manager to support creating and renaming folders within custom projects.
- [API-3323, SQ-650]: Improvement to allow users to change the access log timestamp format to ISO format and allows users to change the timezone for the access log timestamps.
- [API-3694]: Granular Config Promotion - Admins can now choose which resources they export when using the config promotion feature.
- [API-3810, 4107]: Added new API endpoints for uploading custom dependency libraries for use by user-uploaded drivers and connectors.  JDBC drivers now use fully isolated classloading that is tied into these libraries so that any dependencies needed can be installed without conflicting with our default classes or libraries.
- [API-3850, SQ-1108]: Added "JDBC Fetch Size" field to database content and container nodes in the directory namespace tab and view designer.
- [API-3874]: Added support for synching users and passwords into Entra ID and AD from SaaS instances.
- [API-3888]: Added a search filter to the top list in the Manage Primary Object modal in Directory Namespace > Namespace Design > Object Builder.
- [API-3893, SQ-820]: Added optional feature in the persistent search event listener, that enables buffering of events that modify LDAP entries, with configurable buffer size and flushing intervals. This feature is intended to improve performance when a large burst of events is generated by directory operations. This feature is disabled by default and can be enabled and configured in the Control Panel under a persistent search connector's settings.
- [API-3894, SQ-1102]: Improved the Authorization Endpoint URL, Token Endpoint URL and ClientID fields to now automatically trim on the onBlur event (when the field loses focus) and no trailing spaces are included in the saved configuration payload. The BaseDN and BindDN will still accept trailing spaces. 
- [API-3897]: Removed the deprecated HSQLDB custom data source templates. Restored and updated Microsoft SQL Server driver, making SQL Server data sources/templates functional directly out of the box without the user needing to provide a driver.
- [API-3925]: Updated to OpenJDK 8u482-b08.
- [API-3933, SQ-1132]: Improved the Directory Browser search tabs to provide direct actions, including adding attributes and values, deleting attributes and values, replacing/editing values, testing authentication (where applicable), and refreshing the entry.
- [API-3935]: Expanded per-datasource custom datasource logging to include built-in datasource type templates.
- [API-3944, SQ-662]: External token validators feature now supports multiple "Expected scope" values. They can be specified as a comma separated list of scope values in the token validators page.
- [API-4048]: Migrated File Manager from Classic Control Panel into the new Control Panel. 
- [API-4034]: The Extract Database Schema modal now includes a Catalog Name field, which is passed to the API call that extracts the schema.
- [API-4047]:Added support for Active Directory Password Synchronization, allowing password capture within a sync pipeline to synchronize passwords to another naming context.
- [API-4219, SQ-1329]: Users can create REST API access tokens.
- [API-4281, SQ-1387]: Added support for different LDAP changelog algorithms.
- [API-4293]: Updated warning message under virtual attributes section when user selects a node in the Directory Namespace > Namespace Design.  
- [API-4360]: Added a dropdown menu for connector log levels when editing a connector type, so users no longer need to enter values manually and can choose from OFF, ERROR, WARN, INFO, DEBUG, or TRACE.

- [API-3516]:Fixed an issue that prevented realtime cache refresh for Okta groups.
- [API-3625, SQ-994]: Fixed an issue with user deletion related to views from an Active Directory backend with persistent caching. This fixes an issue where a user that is deleted, restored, and deleted again from the Active Directory backend remains visible in the persistent cache. In order for this fix to work, the naming context's dn has to be provided in the Active Directory Sync connector's configuration.
- [API-3826, SQ-1089]: Fixed an issue where manage Groups did not display dynamic membership rules correctly when Special Attributes were enabled.
- [API-3878, SQ-1052]: Fixed an issue where LDIFZ export would fail when the TLS/SSL secure connection was required by access control.
- [API-3896, SQ-1113]: Fixed an issue where the replication thread gets stuck due to an invalid operation DN.
- [API-3905, SQ-1096]: Validate computed attribute can now distinguish between 2 sibling nodes with the same RDN attribute.
- [API-3916, SQ-1027]: Fixed an issue where the Global Identity Builder authentication settings were not saved to the view the file automatically.
- [API-3929]: Fixed the broken multi-node synchronization of custom connectors between nodes.
- [API-3943, SQ-1020]: Fixed the typo in the birthdate attribute in the default ldapschema_55.ldif file.
- [API-3947]: Fixed the display for a topology with a long name in the synchronization tab.
- [API-3951, SQ-1158]: Fixed an issue where the custom password policy's lockout setting was not functioning properly.
- [API-3952]: Fixed an issue where custom data source connector logs used a different format, updated the default per-datasource and per-plugin logging formats to align with the server’s standard log format.
- [API-3957]: Fixed an issue to support proper quoting for SQL for DataBricks data sources.
- [API-3971]: Fixed an issue that caused a blank page to appear when browsing the baseDN from a backend data source after creating a new data source type.
- [API-3973, SQ-1131]: Fixed an issue where AD‑to‑HDAP global sync topologies could set an incorrect user account control value in the target HDAP store.
- [API-3990]: Fixed an issue where, when creating a real-time cache with Periodic Refresh, clicking Next after the initialization step incorrectly auto‑saved the configuration; the flow now correctly proceeds to the next page without performing an unintended save.
- [API-4012]: Fixed an issue where the Secondary Objects section now resets its displayed data each time a join node is selected, preventing partial or incorrect data from being shown.
- [API-4014, SQ-1180]: Fixed an issue where RadiantOne services could not handle very large HTTP headers, such as those containing large JWT tokens.
- [API-4024, SQ-960]: Fixed an issue so that preprocessing filters can now be added to custom object views.
- [API-4044]: Fixed issue with the RadiantOne Server and RadiantOne LDAP Access log settings not persisting.

In Manual mode, changes consisting only of whitespace or newlines do not enable Save. Newlines are removed before submission and on the backend, including for API updates.
- [API-4160]: Fixed an issue in Log Settings where hidden configurations were briefly displayed after a browser refresh.
- [API-4162, SQ-1212]: Fixed email alert issues so that sending mail no longer fails with a “STARTTLS is required” error, and updating SMTP credentials in the UI now takes effect immediately without restarting the scheduler.
- [API-4183]: Fixed an issue where the Entra ID connector configuration now defaults to API v1.0 instead of beta.
- [API-4198, SQ-1313]: Fixed an issue where the LDAP proxy object builder did not correctly display mapped attributes.
- [API-4214]: Fixed an issue so that all limits now have proper error handling.
- [API-4276]: Fixed an issue where using directory browser, LDAP operations now sends the correct modification request.
- [API-4283]: Fixed an issue that caused add value(s) and delete value(s) of members on Entra ID groups to fail when the value(s) were greater than one.
- [API-4292]: Fixed an issue where editing an LDAP filter for the first time incorrectly displayed an “Error validating filter” message.
- [API-4307]: Fixed an issue where requested attribute settings for real‑time cache connectors were being populated incorrectly.
- [API-4310, SQ-1324]: Fixed an issue where filters beginning with an AND (&) followed by an OR (|) did not work correctly, ensuring these filter combinations now function as expected for both JSON and standard filters.
- [API-4311]: Fixed an issue that prevented creating an organizationalUnit entry in an OpenDJ backend via the directory browser when using a proxy, due to an incorrect name attribute being passed.
- [API-4341]: Fixed an issue in Global Sync where change detection for Entra group topologies only exposed a generic memberdelta attribute, without indicating which members were added versus removed.

## Known Issues

The following issues have been identified in this release and will be addressed in a future release:

- [API-4423]: When creating a proxy using a data source on Identity Data Management v8.4.0 and configuring failover LDAP servers, clicking "Test Connection" reports a connection failure. The proxy itself is functional and browsable in the Directory Browser despite the error. 

- [API-4419]: Creating a custom password policy can unintentionally overwrite the "Dictionary Matching Mode" setting on the Default Policy. For example, if the Default Policy has "Dictionary Matching Mode" set to "Contains Match," creating a new custom policy without enabling dictionary check resets the Default Policy's mode to "Exact Match."

- [API-4420]: During migration import from v7.4.21 to v8.4.0, an IllegalStateException error "(Expected state [STARTED] was [STOPPED])" is logged in PathChildrenCache. The migration itself completes successfully despite the error.

- [API-4421]: After creating an Identity Data Management application using a migration export from v7.4.21, Rule Sets for Rules-Based Transformations are not displayed in the pipeline UI, even though the underlying `.java` code is present.
